# Windows 截图晾衣绳：需求基线与实现方案

这是开发前已确认的需求与方案基线。当前开发状态与验证边界请参阅 README.md；本文保留原始范围和验收要求。

## 1. 产品范围

面向 Windows 11 x64 的本地截图中转站。保留细绳、夹子、半透明玻璃卡片、自然摆动和展开收起的趣味，按 Windows 调整，不要求逐像素复刻。工作名称为“截图晾衣绳”，最终名称和原创图标在发布前确定。

已确认需求：

- 沿用现有截图工具，不拦截 Win+Shift+S，不内置截图、标注或视频功能。
- 接收剪贴板图片；排除携带文本、文件列表的内容，抑制自身复制，重复输入只挂一次。提供暂停剪贴板收图开关。
- 默认监视系统截图文件夹，允许添加目录，只接收启动后新增图片。恢复既有卡片不算导入旧图片。
- 仅主屏幕，单根绳子横向滚动，卡片保持可辨识大小，新图显示最新一端。
- 顶部中央悬停约 300ms 展开，离开收起；支持全局快捷键及托盘入口。
- 新图到达展开约 1.5s；悬停、拖放、菜单操作时保持展开。
- 全屏时继续收图，不自动展开、不响应悬停，快捷键可主动请求展开。
- 默认保留最近 30 张，重启恢复。超出上限移除最旧图片。
- 应用自管图片移除时进回收站；外部原图只取下，不删除。拖出另存文件不受清理影响。
- 拖入文件夹保存成功后取下，拖入聊天软件或编辑器后保留。
- 单击复制原图，双击默认应用打开，中键大图预览。右键另存、定位文件及取下。
- 操作产生轻微摆动并自然停稳，隐藏停止动画，默认无提示音。
- 常驻托盘，开机启动默认关闭，允许手动开启，通过托盘菜单退出。
- 自带运行环境的便携 ZIP，解压双击运行；设置与临时图片放在当前用户数据目录。

以下为可调整的初始实现默认值，不是新增的用户确认事项：简体中文 UI、Ctrl+Alt+T 默认唤出、顶边中央 360 DIP 触发宽度、离开后约 350ms 收起、从左到右按时间排列。快捷键冲突时显示设置入口，不占用其他应用已注册快捷键。

## 2. 技术选择

采用 C# / .NET 10 LTS、WPF、少量 Win32 互操作。发布 win-x64 自包含目录，ZIP 内包含完整运行文件，不以单 exe 为目标。不依赖浏览器或在线服务，不做自动更新。

选择理由：WPF 适合图片、动画、菜单、预览和设置；Win32 补齐托盘、全局热键、剪贴板通知、窗口行为与 Shell 拖放。.NET 10 为当前 LTS，避免新项目从临近支持结束的 .NET 8 起步。见 [.NET 支持政策](https://dotnet.microsoft.com/en-us/platform/support/policy)。

玻璃效果先使用半透明渐变、高光、细边框和阴影实现。需求已允许 Windows 适配，因此首版不把实时桌面模糊列为必要条件；不使用定时截图桌面来模拟玻璃。若早期验证证明需要更强材质，再单独评估 Composition，并保留纯 WPF 回退。系统材料不直接等价于任意透明卡片的背景模糊，不能只启用一个整窗 Acrylic 就视为完成。见 [Windows 材料说明](https://learn.microsoft.com/en-us/windows/apps/develop/ui/materials)。

## 3. 模块与数据流

输入源 → 图片验证与标准化 → 来源合并与去重 → 卡片状态 → 浮层展示与操作。

| 模块 | 负责内容 |
|---|---|
| Core | 卡片、文件归属、收图规则、容量、展开状态机、拖放结果规则；不依赖 WPF |
| Windows | 剪贴板、已知文件夹、目录通知、快捷键、前台窗口、回收站、Shell 拖放和启动项 |
| Media | 后台图片解码、缩略图、像素哈希、格式和尺寸限制 |
| Storage | 设置、卡片索引、收件箱、原子保存及恢复 |
| UI | 绳子、卡片、动画、命中区域、预览、菜单与设置 |

建议目录：src/Clothesline.Core、src/Clothesline.Windows、src/Clothesline.App、tests/Clothesline.Core.Tests、tests/Clothesline.Windows.Tests。Clothesline 仅为代码命名占位，不作为最终品牌。

卡片记录包含 ID、加入时间、原始路径、自管/外部归属、缩略图路径、图像尺寸和来源。归属由创建过程记录，不能只根据字符串路径猜测；清理操作再次核验路径位于自管目录且不是重解析点跳转。

## 4. 收图与存储

剪贴板通过 AddClipboardFormatListener/WM_CLIPBOARDUPDATE 接入；读取在 STA 线程完成，图片解码和哈希后台执行，剪贴板占用时有限重试。图片优先读取 PNG，兼容 DIB；覆盖透明像素、零 alpha、超大图和无效数据场景。文本、文件列表、可识别隐私标记应在解码前过滤。自身复制通过序列号及内容指纹联合抑制，不能只设置一个短时布尔开关。

目录使用 FileSystemWatcher，覆盖新增、重命名、延迟完成写入；有限重试确认文件可解码，缓冲区溢出时执行有界补扫。先建立监听，再获取启动基线以降低漏图风险。系统截图目录按已知文件夹定位，不能硬编码 C:\\Users 或英文 Pictures；支持目录重定向。缺失目录不阻止其他来源工作。

为不同编码的同一图片计算标准化像素指纹，在短时间窗口内合并不同来源。保留外部原图路径作为关联信息；重复到达不会生成两张卡，也不会因合并而删除原图。同一图片隔较长时间再次复制允许再次挂上。

建议初始格式 PNG、JPEG、BMP、TIFF、静态 GIF；WebP/HEIC 等运行时无法可靠解码时跳过并记录原因，不把缺少编解码器误报为收图成功。初始限制 64MiB、80MP，超过限制在托盘状态中给出可理解提示，避免无声丢弃或内存失控。

数据放在 %LOCALAPPDATA%/<最终应用名>/：settings.json、items.json、Inbox/、Thumbnails/、logs/。索引先写临时文件再替换；异常退出后恢复索引、核对路径，不启动即扫描删除所有“孤儿”图片。清理失败保留待重试记录；不能先忘记图片再假装回收成功。回收站不可用时保留文件并报告，不转为永久删除。

## 5. 窗口和交互

WPF 无边框透明浮层不出现在任务栏，不抢输入焦点。空白处穿透，卡片、菜单等可交互区域接收鼠标。隐藏时真正隐藏窗口，不留下整条透明遮挡。顶边触发优先用低频指针检测，不放置抢占系统边缘的不可见点击条；空队列不弹空面板。

采用统一状态机 Hidden、HoverPending、Revealed、AutoPeek、Dragging、MenuOpen；预览作为独立交互状态。所有展开/收起事件归一处理，避免一个计时器在拖放中收起、另一个又展开。主屏变更、分辨率与缩放变化、休眠恢复后重新计算位置。即使只展示主屏，也必须处理主屏为 125%/150%/200% 的情况。

图片点击等待系统双击判定间隔后复制；双击取消等待的复制并打开，避免打开图片时意外改写剪贴板。拖动超过系统阈值后进入 OLE，不再触发点击。预览支持 Escape 关闭，不劫持其他应用快捷键。

全屏判断结合前台窗口、显示器边界和 Shell 状态，排除本应用自身。快捷键唤出属于明确操作，但无法保证浮层覆盖独占全屏或受保护桌面；如果系统不允许，保留托盘入口，不通过注入或提权绕过。

## 6. 拖放与文件安全

使用 Shell/OLE，提供现有文件路径与合适的图片数据格式，支持取消恢复。拖放适配器独立于视图。

“拖进文件夹保存后取下”是高风险验收项：仅凭 DoDragDrop 返回 Copy/Move，无法可靠认定目标是文件夹还是应用。实现需要处理 Shell 完成效果、目标能力及文件实际状态，优先提供应用自管的暂存副本参与传输，避免误移动外部原图。

只在确认保存/移动完成后取下。无法确认时保留卡片，不删除原图，允许通过右键另存作为明确保存路径。这是失败保护，不等于目标功能通过验收；必须单独报告哪些文件夹和接收应用达到约定行为。跨盘、同盘、取消、同名冲突、拒绝访问都要验证。参考 [Shell 剪贴板格式和拖放结果](https://learn.microsoft.com/en-us/windows/win32/shell/clipboard)。

## 7. 开发阶段

| 阶段 | 交付与通过条件 | 估算 |
|---|---|---|
| 0 技术验证 | 透明穿透、不抢焦点、拖放完成反馈、主屏缩放；证明采用方案能满足关键行为 | 2–3 个工作日 |
| 1 收图闭环 | 剪贴板+目录、去重、30 张容量、索引恢复、回收站规则；暂用基础卡片 | 3–5 个工作日 |
| 2 核心交互 | 展开状态机、全屏避让、复制/打开/预览、滚动、另存和拖放 | 4–6 个工作日 |
| 3 视觉打磨 | 绳子夹子、玻璃卡片、弹簧摆动、新图展示、暗亮主题适配 | 3–5 个工作日 |
| 4 交付验证 | 场景矩阵、性能、启动项、干净环境运行、自包含 ZIP、中文说明与校验值 | 3–5 个工作日 |

合计约 15–24 个工作日，前提是熟悉 Windows 桌面开发且能使用真实桌面验证。为规划估算，不是未经原型验证的工期承诺。阶段 0 若无法满足拖放语义或材质要求，先记录具体差距与替代实现，再调整方案，不带着已知缺口进入视觉打磨。

## 8. 验收清单

- Win+Shift+S、Win+PrintScreen、至少一种用户实际使用的第三方截图工具：图片到达、正确显示、重复来源仅一张。
- 文本、Excel 单元格、文件列表、自身复制：不新增卡片；普通复制图片按规则接收。
- 监视目录启动前的图片不挂上；延迟写入、重命名和重复通知不漏收、不重复。
- 单击复制全尺寸、双击打开、中键预览、右键另存/定位/取下均正确。
- Explorer 同盘/跨盘文件夹保存、至少两个实际使用的应用接收、取消与拒绝操作：逐项核对结果与文件存留。自动接收器测试不能代替真实应用。
- 第 31 张到达、手动取下、正常退出、强制终止后重启：顺序、容量、归属与回收站规则正确，外部文件不丢失。
- 顶部悬停、1.5s 新图提示、拖放和菜单保持、全屏继续收图与快捷键主动请求：无状态冲突。
- 主屏 100%/125%/150%/200%，主屏切换、分辨率变化及休眠恢复：位置与命中正确。
- 空白区域点击和滚轮能到达下方应用；卡片操作不抢焦点；隐藏窗口不残留遮挡。
- 30 张大图时原图不常驻解码，缩略图有界缓存；隐藏无动画帧循环。参考机上隐藏空闲 CPU 目标接近 0%、稳定低于 0.5%，活动动画目标 60fps。实际报告注明硬件、采样方法和结果，不以构建通过代替性能验证。
- 无 .NET 的干净 Windows 11 x64 普通用户环境：解压运行、设置恢复、开机启动开关与退出可用；未完成此项则明确标注环境限制。
